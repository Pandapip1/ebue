# Known, fenced instances of the defect tools/lint-widthmod.sh checks for.
# Reported on every run and not counted as findings; a NEW site fails.
#
# One entry per line: FILE<TAB>the exact source line (leading and trailing
# whitespace trimmed)<TAB>the reason and where the fence is.
#
# Keyed on the line TEXT, not its number, because a number goes stale on
# any edit above it and a stale key stops matching silently.  An entry
# that matches nothing is a hard failure -- see that script for why.
#
# DELETE AN ENTRY IN THE SAME COMMIT THAT FIXES ITS SITE, and unfence the
# test that records it.  That is the whole point of keeping this where a
# machine reads it.
#
# The list is currently EMPTY, and that is a real state, not a missing
# file: printf.c's three sites were fixed in c200c7f and their entries
# removed here.  An empty list means every LM_z/LM_t site in the tree is
# judged on its merits, with nothing excused; the scan's own floors
# (see tools/lint-widthmod.sh) still fail a run that judged nothing, so
# emptiness here cannot make the stage vacuous.
#
