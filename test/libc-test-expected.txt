# test/libc-test-expected.txt -- the adjudication ledger for
# third_party/libc-test, read by tools/libc-test.sh.
#
# One or more profile rules per corpus test:
#
#     <name>  <profile selector>  <disposition>  <reason>
#
# The dispositions are PASS, BUG, UNIMPL, NA and FLAKY.  Every non-PASS
# row requires a reason.  Compiler/process observations remain separate:
# pedantic requires BUG to build and fail and UNIMPL not to build; strict
# performs those probes and then rejects either disposition.
#
# A disposition may be overridden by adding a more specific profile rule.
# Profile dimensions include runtime, target and host architecture, WOW64,
# kernel32 support and named runtime capabilities. The shared resolver
# rejects ambiguous matches and profiles for which no rule exists. This
# baseline deliberately claims only the configuration in which it was measured;
# another platform must be annotated before it can use the ledger.
#
# This file does NOT need one row per real case. It lists only the cases
# whose disposition deviates from PASS, plus one trailing wildcard row
# (case "*") that declares PASS as this corpus's own default for every
# case with no more specific row. That row is not decoration:
# tools/testlib.py's resolve() falls back to a case="*" rule whenever a
# case-specific search comes up empty, so "everything else is PASS" is a
# real, matched rule here, not a hidden default in Python or in
# tools/libc-test.sh. Which cases are "real" -- so that a case with no row
# here still gets adjudicated, rather than silently dropped -- comes
# independently from tools/libc-test.sh's own glob over
# third_party/libc-test/src/{functional,regression}/*.c (see its
# read_ledger()), not from what happens to be listed below. This mirrors
# test/posix-opts-expected.txt's own wildcard row exactly (see commit
# 93bbaa3, "test: default posix-opts cases to PASS via an explicit
# wildcard row"); this ledger previously took the opposite position --
# every real case needed an explicit row, and an absent one was a hard
# error -- until the project decided that PASS-by-default is fine here
# too, as long as the default is a real, visible row rather than a
# hidden one.
#
# Baseline: ntlibc 661c577, libc-test 68edb8b, x86_64-win32-tcc, under
# the project's patched Wine (which implements RtlCloneUserProcess, so
# nothing here is Wine-fork-blocked; on stock Wine several of these
# become NA at run time instead, by design).
#

# pthread_mutex, pthread_mutex_pi, pthread_once-deadlock, tls_get_new-dtv)

# tree with x86_64-win32-tcc: pthread.h no longer blocks any of them, but
# none newly resolves to a clean build either -- each now fails for a
# different, unrelated, real reason (see each row): the 4 pthread_* ones
# because their test source includes only pthread.h (no time.h) and this
# library's pthread.h does not expose CLOCK_REALTIME, and tls_get_new-dtv
# because it hits the same unresolved '__rpath' gap as the dlopen/
# tls_align_dlopen/tls_init_dlopen rows below. daemon-failure's reason was
# also reworded to note that daemon() is deliberately unimplemented
# (include/unistd.h's own "undefined-ok" comment), not an open gap;
# crypt's reason was checked and is still accurate as written (no
# crypt.h-declined-on-purpose banner exists anywhere in this tree, unlike
# daemon()). No disposition or COUNTS changed by this refresh: all 6
# reworded rows keep their prior disposition, just an accurate, current
# reason. This refresh's environment had a working x86_64-win32-tcc but
# no runnable x86_64 Wine (see test/posix-opts-expected.txt's own refresh
# note for what was tried and why it did not work), so this pass verified
# compile/link outcomes only, not runtime behaviour.
#
# ipc_msg/ipc_sem/ipc_shm moved from UNIMPL to the PASS default in the
# XSI-IPC pass that added <sys/ipc.h>/<sys/shm.h>/<sys/msg.h>/<sys/sem.h>
# -- see test/posix-ipc.c. Verified by building and running the
# unmodified upstream ipc_shm.c/ipc_msg.c/ipc_sem.c natively against
# this project's Linux backend (real shmget(2)/msgget(2)/semget(2)
# syscalls): every assertion passes except shm_perm.gid/cgid (and the
# msg_perm/sem_perm equivalents), which fail for a pre-existing,
# unrelated reason already tracked separately -- getgid()/getegid()
# (src/unistd/ids.c) are hardcoded to 1000 rather than reading the real
# credential, so ntlibc's own getegid() disagrees with the value the
# real kernel stamped into shm_perm.gid at shmget() time. The NT backend
# does not share that failure mode: it populates ipc_perm.{uid,gid}
# FROM this project's own geteuid()/getegid() at creation time (src/ipc/
# nt/plat_{shm,msg,sem}.c), so the corpus test's `== geteuid()/getegid()`
# assertions compare against the same function on both sides by
# construction, whatever that function returns. NT itself could not be
# executed to confirm this end to end: this environment's Wine could not
# be brought up at all under the qemu-user x86_64-on-aarch64 translation
# available here (wine-preloader: "Unable to find a guest_base to
# satisfy all guest address mapping requirements", reproduced across
# two qemu versions and unrelated to this change), and this baseline's
# own note above already records that Wine needs the project's patched
# build (RtlCloneUserProcess) for XSI IPC's fork()-based test shape
# regardless. This PASS therefore rests on real Linux execution of the
# identical upstream source plus code review of the NT backend, not on
# an observed Wine run -- flagged here for whoever next runs this
# ledger's probe against real Wine to confirm.
#
