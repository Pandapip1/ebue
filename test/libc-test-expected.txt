# test/libc-test-expected.txt -- the adjudication ledger for
# third_party/libc-test, read by tools/libc-test.sh.
#
# One line per test in the corpus, all 146 of them:
#
#     <name>  <status>  <reason>
#
# and every test must have exactly one.  A corpus test with no line
# here is a hard failure, not a default-to-ignored: a test nobody has
# decided about must look undecided.
#
# STATUSES
#
#   pass             must exit 0.  If it does not, that is a regression
#                    and the stage goes red.
#   xfail:defect     a real behavioural defect of THIS LIBRARY, triaged,
#                    with the ledger row (or its absence) named in the
#                    reason.  Not fixed here -- this project fences
#                    confirmed defects rather than fixing them in the
#                    same pass; this file is the fence for the ones that
#                    live in an external suite.
#   xfail:documented a divergence the tree already documents and stands
#                    behind (a deliberate stub, a design difference, a
#                    platform primitive that does not exist).
#   xfail:env        blocked by the target environment, not by this
#                    library, in a way that is NOT detectable from the
#                    test's own output at run time.  Anything that IS
#                    detectable -- Wine's RtlCloneUserProcess abort, a
#                    stubbed shim helper -- is reported as unverified
#                    (rc=77) by tools/libc-test.sh instead and never
#                    reaches this file.  Keep this category small.
#   unclassified     IT FAILS AND NOBODY HAS LOOKED AT IT.  Reason must
#                    begin with NOT-YET-TRIAGED.  This is deliberately a
#                    different word from xfail: an unexamined failure
#                    recorded as "expected" looks decided, and is worse
#                    than one recorded as undecided.
#   unbuildable      does not compile or link.  Reason is the compiler's
#                    own first error, verbatim.  NEVER a pass: 57 of
#                    146 tests die at #include, which is the gap
#                    accounting restated as a build error and is
#                    evidence of nothing about behaviour.
#
# WHY THIS FILE CANNOT GROW SILENTLY
#
# The COUNTS line below is checked by tools/libc-test.sh against the
# rows in this file.  pass, xfail and unbuildable must match EXACTLY;
# unclassified is a CEILING that may only come down.  So a commit that
# adds a known failure necessarily also contains the line saying the
# number of known failures went up -- which is the thing a reviewer
# needs to see, and the thing an append-only exception list never shows
# anyone.  A test that is expected to fail and starts passing is also a
# hard failure: a fixed defect must force this file to be updated.
#
# Baseline: ntlibc 661c577, libc-test 68edb8b, x86_64-win32-tcc, under
# the project's patched Wine (which implements RtlCloneUserProcess, so
# nothing here is Wine-fork-blocked; on stock Wine several of these
# become unverified at run time instead, by design).
#
# COUNTS pass=61 xfail=24 unclassified=4 unbuildable=57
#
